# Bezpečnostní audit mIDE — 26. 10. 2026

## Aktualizace 27. 10. 2026 — opravy dokončeny

A-01 až A-04 jsou opraveny a regresně ověřeny v pracovním adresáři. Níže uvedený audit z 26. října je historický záznam původních nálezů; původní čísla řádků a hash popisují tehdejší stav.

- **A-01:** HTTP/1.1 parser vyžaduje jediný Host přesně odpovídající `127.0.0.1:<aktivní port>` nebo `localhost:<aktivní port>`. Odmítá neplatnou syntaxi, absolutní/protokolově relativní request target, duplicitní Host, transfer encoding a těla požadavků. Skryté komponenty cest se blokují v URL, kanonickém cíli, indexu i výpisu; kořenová `.well-known` je explicitní výjimka bez skrytých potomků.
- **A-02:** dekódované řídicí znaky se odmítají, segmenty Location se procentně kódují. Serializace hlaviček obsahuje další kontrolu řídicích znaků.
- **A-03:** odkazy výpisu mají prefix `./` a procentně kódovaný segment, oddělený od HTML-escapovaného zobrazovaného názvu.
- **A-04:** všechny klientské sockety jsou neblokující; každý průchod provádí omezený objem IO. Limit je 16 spojení, z toho nejvýše 8 SSE. Celý požadavek musí přijít do 5 sekund, odesílání odpovědi či SSE zprávy má absolutní limit 10 sekund. Odpojené SSE se pravidelně odstraňují i bez změn souborů. Přijímání spojení a zpracování reload fronty mají omezené dávky, aby nezablokovaly stop. Ukončení zavře všechny sockety. Souborové čtení je omezené na 16 MiB (+ jeden detekční bajt), zápisy na socket probíhají nejvýše po 64 KiB za průchod; seznam adresáře je omezen na 2 048 položek.

Zvolená implementace má omezené paměťové buffery; nejde o neomezené streamování velkých souborů. Lokální diskové operace zůstávají synchronní: nedostupný síťový mount nebo aktivní souběžné změny souborového systému nejsou těmito síťovými limity vyřešeny. Skryté soubory se filtrují podle názvu/cíle, nikoli podle obsahu; tajemství uložené do běžného veřejného souboru nelze automaticky rozpoznat. Prohlížečové end-to-end ověření DNS rebinding ani Windows/macOS runtime nebyly provedeny.

## A-01 — Chybí kontrola Host a Go Live zpřístupňuje citlivé soubory

**Priorita: vysoká. Potvrzeno na HTTP vrstvě; úplný DNS rebinding útok v prohlížeči nebyl proveden.**

Místo: `src-tauri/src/live_server.rs:305` (`read_request`), `:200` (`respond`), `:248` (`file_reply`).

Parser zahodí všechny hlavičky. Server proto přijme i požadavek s cizím Host. Současně zpřístupňuje libovolné běžné soubory uvnitř projektu včetně `.env` a `.git/config`; výpis adresáře obsahuje i skryté položky.

Ověření: dočasný `.env` s hodnotou `AUDIT_DUMMY=not-a-real-secret`, požadavek `GET /.env` s `Host: attacker.invalid:5500` a odpovídajícím Origin vrátí HTTP 200 a obsah souboru.

Dopad: klient s přístupem k lokálnímu portu čte soubory projektu bez autentizace. Chybějící kontrola Host vytváří předpoklad pro DNS rebinding z útočníkovy stránky; skutečná vzdálená zneužitelnost závisí na prohlížeči, ochranách přístupu k lokální síti a DNS. Samotný test neprokazuje obejití těchto ochran. Loopback vazba brání přímému přístupu z LAN, ale není náhradou kontroly Host.

Oprava: striktní parsování HTTP a allowlist očekávaných lokálních autorit včetně portu, odmítnutí chybějícího či duplicitního Host; samostatná pravidla pro citlivé soubory a adresáře, aplikovaná i na přímé URL a kanonické cíle symlinků. Povolené veřejné výjimky, například `.well-known`, definovat explicitně. Zvážit náhodný token relace jako další vrstvu. Pouhé vypnutí CORS tento typ problému neřeší.

Regresní ověření: cizí Host vrací chybu, `.env`, `.env.local`, `.git/config` nejsou dostupné ani přes alias/symlink, běžné HTML/CSS funguje.

Kontext: [Vite — riziko DNS rebinding při povolení libovolných hostů](https://main.vitejs.dev/config/server-options#server-allowedhosts).

## A-02 — Název adresáře umožňuje vložení HTTP hlavičky

**Priorita: střední. Potvrzeno v bajtech HTTP odpovědi na Linuxu.**

Místo: `src-tauri/src/live_server.rs:172` (`redirect_location`), `:330` (`write_reply`).

URL se procentně dekóduje a název adresáře se bez URL kódování vloží do Location. Linux dovoluje CR/LF v názvu souboru nebo adresáře.

Ověření: adresář pojmenovaný `dir\r\nX-Audit: injected` a požadavek `/dir%0D%0AX-Audit:%20injected` vytvoří samostatnou hlavičku `X-Audit: injected/`.

Podmínky: takový adresář musí existovat v otevřeném projektu a uživatel/klient musí vyžádat příslušnou cestu bez koncového lomítka. Lze jej dodat jako součást nedůvěryhodného projektu. Test neověřoval navazující zneužití v konkrétním prohlížeči.

Dopad: útočníkem řízené hlavičky odpovědi; další dopady závisejí na konkrétním payloadu a klientovi.

Oprava: URL-kódovat jednotlivé segmenty Location, odmítat řídicí znaky a generovat HTTP hlavičky přes typované API ověřené HTTP knihovny.

Regresní ověření: CR/LF nemůže vytvořit novou hlavičku; mezery, Unicode, `?` a `#` v názvech se správně kódují.

Klasifikace: [CWE-113](https://cwe.mitre.org/data/definitions/113.html).

## A-03 — Výpis adresáře generuje odkazy se schématem javascript:

**Priorita: střední. Potvrzeno v generovaném HTML; kliknutí v prohlížeči nebylo automatizováno.**

Místo: `src-tauri/src/live_server.rs:150` (`directory_listing`), zejména sestavení `href`.

HTML escapování názvu nebrání tomu, aby byl název interpretován jako URL schéma. Soubor `javascript:alert(1)` vytvoří `<a href="javascript:alert(1)">…</a>`.

Podmínky: nedůvěryhodný projekt obsahuje takový název, adresář nemá index.html a uživatel klikne na položku výpisu. HTTP výpis nemá CSP; CSP hlavního Tauri okna se na externí prohlížeč nevztahuje.

Dopad: nebezpečný odkaz může spustit JavaScript v původu Go Live. Tento původ zpřístupňuje další soubory projektu. Nejde o prokázané spuštění kódu v privilegovaném Tauri okně.

Oprava: odkazy vytvářet jako explicitní relativní cesty s prefixem `./`, URL-kódovat jméno jako jeden segment a následně HTML-escapovat atribut. Zobrazovaný text escapovat odděleně.

Regresní ověření: názvy začínající `javascript:`, `data:` nebo obsahující `#`, `?`, uvozovky se vždy chovají jako názvy souborů.

## A-04 — Pomalý klient může blokovat obsluhu i zastavení Go Live

**Priorita: střední. Potvrzeno zpoždění zastavení neúplným požadavkem; dlouhodobé vyčerpání prostředků nebylo zatěžovacím testem prováděno.**

Místo: `src-tauri/src/live_server.rs:305`, `:351` (`serve`), `:473` (`stop_running`).

Jediné obslužné vlákno blokujícím způsobem čte požadavek a zapisuje odpověď. Pětisekundový timeout se vztahuje na jednotlivá čtení, nikoli na dokončení celého požadavku. Zápis nemá timeout. Zastavení čeká přes `join()` na dokončení tohoto vlákna.

Ověření: klient odešle neúplné hlavičky a ponechá spojení otevřené. Po odeslání signálu stop server ani po dalších 350 ms neskončí; po uzavření klienta se ukončí. Průběžné posílání bajtů může opakovaně obnovovat čas na čtení. Obdobně klient, který nečte velkou odpověď, může blokovat zápis. Tyto delší varianty vyplývají z kódu, nebyly end-to-end reprodukovány.

Dopad: nedostupnost Go Live a potenciální blokování akcí aplikace čekajících na zastavení serveru.

Další související slabiny: `file_reply` čte celý soubor do paměti bez limitu (na rozdíl od editoru); SSE klienti se ukládají bez limitu a odpojení se kontroluje až při reloadu. Zvyšují riziko vyčerpání paměti či deskriptorů; skutečný pád nebyl vyvoláván.

Oprava: zrušitelná obsluha spojení mimo hlavní accept smyčku, absolutní deadline požadavku, write timeout, limit aktivních/SSE spojení, pravidelný úklid a omezené streamování souborů. Zastavení musí ukončit i aktivní sockety.

Regresní ověření: neúplný požadavek ani pomalý čtenář nezablokují druhého klienta nebo stop; limity jsou ověřeny malými testovacími hodnotami.

## Pozitivní zjištění a další doporučení

- Go Live naslouchá pouze na IPv4 loopbacku. Kontroluje `..` a běžné úniky přes symlinky, včetně index.html.
- Souborové API ověřuje kanonické cesty a příslušnost k projektu. Čtení má limit 16 MiB; ukládání používá nový dočasný soubor a kontroluje změny na disku.
- Kontroly cest a následné operace nejsou atomické vůči souběžné změně adresářů/symlinků. Odolnost vůči lokálnímu procesu aktivně měnícímu projekt není prokázána. Pro silnou hranici zvážit operace relativní k otevřenému adresáři a bezpečné resolve flagy. Aktivní závod nebyl reprodukován, proto není započten mezi čtyři potvrzené nálezy.
- Formátování používá přibalené pluginy a explicitní parser; kontrolovaný kód nevolá načtení projektové konfigurace Prettier. Argumenty Node se nepředávají přes shell. Chybí však deadline procesu a limit výstupu; doporučeno doplnit.
- Témata mají omezení velikosti a povolených hodnot. Externí odkazy omezují schémata na HTTP/HTTPS. Obrázky se načítají jako data URL přes obrázkové API, nikoli jako HTML dokument s oprávněními aplikace.
- Tauri má CSP a omezený seznam oprávnění pluginů. Vlastní příkazy ovšem zahrnují otevření libovolného projektu a terminál; bezpečnost privilegovaného UI zůstává zásadní. Nebyl nalezen doložený vstup umožňující jeho kompromitaci.
- CI spouští testy, ale nemá automatickou kontrolu známých zranitelností. Doplnit npm audit obou lockfile, RustSec kontrolu, hlášení zranitelností v SECURITY.md, připnutí CI akcí na SHA a ověřitelný původ vydání. SHA256SUMS samo neověřuje identitu vydavatele.
